## 출력 규칙

- 이 스킬로 답할 때 **첫 줄에 `[qgis-connect-check 1.0.3]` 을 쓴다.** 예외 없다.
- 그 아래에 점검표를 적는다. 잰 값을 그대로 적고 요약하지 않는다.

## 이 스킬이 하는 일

QGIS 가 살아 있는지, MCP 서버가 붙었는지, 버전이 강의 기준과 같은지를 한 번에 확인한다.
다른 QGIS 작업을 시작하기 전에 먼저 부른다. 연결이 끊긴 채로 전처리를 시작하면 절반쯤에서 멈춘다.

이 스킬은 **읽기만 한다.** 레이어를 만들지 않고 프로젝트를 바꾸지 않는다.

## 기준 환경

| 항목 | 강의 기준값 |
|---|---|
| QGIS | 3.44 LTR |
| QGIS MCP 플러그인 | 0.14.0 |
| MCP 서버 | `uvx --from https://github.com/nkarasiak/qgis-mcp/archive/refs/tags/v0.14.0.zip qgis-mcp-server` |
| 포트 | 127.0.0.1:9876 |

## 절차

### 1. 연결

qgis MCP 서버의 `ping` 을 호출한다.

- `pong` 이 오면 통과다.
- 실패하면 **거기서 멈추고** 아래 "연결이 안 될 때" 를 그대로 안내한다. 다음 단계로 넘어가지 않는다.

### 2. QGIS 버전

`get_qgis_info` 를 호출한다. 돌아온 버전 문자열을 **그대로** 적는다.

- `3.44` 로 시작하면 기준 환경과 같다.
- 다르면 그 값을 적고 "강의 기준(3.44 LTR)이 아니다" 를 함께 알린다. 실패로 보지는 않는다.
  실습은 대체로 돌아가지만 도구 동작이 미묘하게 다를 수 있다.

### 3. 플러그인 버전 (가능하면)

`get_plugin_info` 로 QGIS MCP 플러그인의 버전을 읽는다.
값이 안 나오면 `list_plugins` 로 목록을 받아 이름에 `qgis` 와 `mcp` 가 함께 들어간 항목을 찾는다.

- 0.14.0 이면 기준과 같다.
- 두 방법 다 값을 못 주면 **추측하지 말고** "확인 불가" 로 적는다. 이 항목은 실패 사유가 아니다.

### 4. 프로젝트 상태 (선택)

`get_project_info` 로 열려 있는 프로젝트와 프로젝트 CRS 를 확인한다.
실습 프로젝트 CRS 는 EPSG:5186 이다. 다르면 알려만 준다. 여기서 고치지 않는다.

### 5. 보고

아래 형식으로 답한다. 칸을 비우지 않는다.

```
[qgis-connect-check 1.0.3]
연결: pong
QGIS: <get_qgis_info 가 준 문자열 그대로>   (기준 3.44 LTR / 일치·불일치)
플러그인: <버전 또는 확인 불가>            (기준 0.14.0 / 일치·불일치)
프로젝트 CRS: <값 또는 열린 프로젝트 없음>  (기준 EPSG:5186)
판정: 사용 가능 / 사용 불가 — <사유>
```

## 연결이 안 될 때

아래 순서로 짚는다. 대부분 1번과 2번에서 끝난다.

1. **QGIS 가 떠 있는가.** 창이 하나도 없으면 QGIS 부터 실행한다.
2. **플러그인의 Start Server 를 눌렀는가.** QGIS MCP 도크 위젯에서 서버를 켜야 포트가 열린다.
   이 칸을 가장 자주 빠뜨린다.
3. **포트가 열렸는가.** Windows PowerShell 에서 확인한다.

   ```
   Test-NetConnection 127.0.0.1 -Port 9876
   ```

   `TcpTestSucceeded : True` 여야 한다. False 면 QGIS 쪽 문제다. MCP 클라이언트를 재시작해도 소용없다.
4. **MCP 서버가 등록돼 있는가.** 등록 자체가 없으면 도구 목록에 `ping` 이 아예 안 보인다.
   강의 배포 플러그인을 설치했다면 플러그인의 `.mcp.json` 이 등록을 대신한다.
5. 여기까지 다 맞는데도 실패하면 QGIS 를 재시작하고 Start Server 를 다시 누른다.

QGIS 를 껐는데 `qgis-mcp-server` 프로세스가 여러 개 남아 있는 경우가 있다.
포트 9876 이 닫혀 있으면 QGIS 쪽 문제이지 그 프로세스 탓이 아니다. 신경 쓰지 않아도 된다.

## 하지 않는 것

- 연결 복구를 자동으로 시도하지 않는다. QGIS 실행과 Start Server 는 사람이 누른다.
- `execute_code` 를 쓰지 않는다. 이 점검에 필요한 값은 전부 전용 도구로 읽을 수 있다.
- 값을 확인하지 않은 채로 "연결됐다" 고 보고하지 않는다.
